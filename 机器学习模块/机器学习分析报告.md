# 纽约公共自行车(Citi Bike)机器学习分析报告

**成员4：机器学习模块 — KMeans站点聚类 + 骑行时长预测 + 客流预测**

---

## 一、项目概述

本报告基于纽约Citi Bike公共自行车系统2026年6-7月的20万条骑行记录，运用无监督聚类和有监督回归两类机器学习方法，完成三项核心分析：

1. **KMeans站点聚类**：对1985个有效站点进行无监督分类，通过SSE、轮廓系数、CH指数、DB指数四指标综合确定K=4，识别四类不同特征的站点（高流量通勤枢纽、中流量通勤站、低流量通勤站、低流量休闲站），为车辆调度和站点规划提供数据支撑。
2. **骑行时长预测**：基于骑行距离、时间、用户类型、站点热度等17维特征，对5种回归模型横向对比（另加2种朴素基线），最佳模型随机森林R²=0.2030，MAE=4.802分钟；骑行距离distance_km为第一重要特征（贡献61.84%）。
3. **小时级客流预测**：基于时间序列特征（滞后项、滑动平均、周期编码），对5种回归模型横向对比（另加2种朴素基线），最佳模型梯度提升R²=0.9459，MAE=29.96次/小时；滞后客流lag_1h为第一重要特征（贡献79.41%）。

## 二、数据说明

### 2.1 数据来源

- 原始数据：成员2预处理后的 `clean_citibike.csv`
- 原始记录数：200,000条
- 距离异常值(>50km)过滤后：200,000条（本数据集无超阈值异常）
- 时间范围：2026-06-30 至 2026-07-31
- 站点数：2,292个（聚类时过滤低流量站后保留1,985个）

### 2.2 核心字段

| 字段 | 类型 | 说明 |
|------|------|------|
| ride_duration | float | 骑行时长（秒） |
| start_time / end_time | datetime | 起止时间 |
| start_station / end_station | string | 起止站点名称 |
| start_lat/lng, end_lat/lng | float | 起止站点经纬度 |
| user_type | string | 用户类型：Subscriber(会员)/Customer(临时) |
| rideable_type | string | 车辆类型：classic(经典)/electric(电动) |
| hour / weekday / is_weekend | int | 时间衍生特征 |

### 2.3 衍生特征

本模块在原始数据基础上计算了以下关键衍生特征：

- **duration_min**：骑行时长（分钟）= ride_duration / 60
- **distance_km**：Haversine球面距离（公里），基于起终点经纬度计算
  - 公式：`d = 2R × arcsin(√(sin²(Δlat/2) + cos(lat1)cos(lat2)sin²(Δlng/2)))`
  - 平均距离2.08km，中位数1.56km
- **站点级聚合特征**：total_trips, avg_duration, peak_hour, morning/evening_peak_ratio, weekend_ratio, subscriber_ratio, flow_balance等10维

## 三、KMeans 站点聚类分析

### 3.1 方法设计

#### 3.1.1 特征工程（10维）

对每个站点聚合以下特征：

| 特征 | 含义 | 业务解读 |
|------|------|---------|
| total_trips | 总骑行量(借出+借入) | 站点活跃度 |
| avg_duration | 平均骑行时长(分钟) | 站点服务的出行距离类型 |
| peak_hour | 最活跃小时 | 站点使用时间模式 |
| morning_peak_ratio | 早高峰(7-9点)占比 | 是否为通勤出发站 |
| evening_peak_ratio | 晚高峰(17-19点)占比 | 是否为通勤到达站 |
| weekend_ratio | 周末骑行占比 | 休闲属性强度 |
| subscriber_ratio | 会员占比 | 用户结构 |
| flow_balance | 流入流出平衡度 | 是否需要调度干预 |
| lat / lng | 经纬度 | 空间位置 |

#### 3.1.2 数据预处理

- 标准化：StandardScaler（消除量纲差异，流量和占比尺度差异大）
- 过滤：总流量<20的站点视为边缘/异常站点，排除后保留1,985个有效站点

#### 3.1.3 选K方法（四指标综合判定）

不依赖单一指标，同时计算四项聚类评估指标：

| 指标 | 含义 | 选择方向 |
|------|------|---------|
| SSE（肘部法则） | 簇内平方和 | 找下降拐点 |
| 轮廓系数(Silhouette) | 簇内紧密度/簇间分离度 | 越高越好 |
| CH指数 | 簇间方差/簇内方差 | 越高越好 |
| DB指数 | 平均簇间相似度 | 越低越好 |

**选K结果**（K=2~10扫描）：
- 肘部拐点：K=4（SSE二阶差分最大处）
- 轮廓系数最优：K=2（但K=4处轮廓系数0.1624仍属合理区间）
- 综合判定：**K=4**——SSE肘部拐点与业务解释性最优，四类站点画像清晰可操作

**业务解读**：

- **簇0（低流量休闲站，287站）**：周末占比33.4%全场最高、平均时长17.8分钟最长、会员占比65.5%最低——典型休闲骑行站点（滨水/公园区域）。

## 四、骑行时长预测分析

### 4.1 问题定义

- **目标变量**：duration_min（单次骑行时长，分钟）
- **任务类型**：回归预测
- **训练/测试划分**：随机80/20划分（160,000 / 40,000条，固定随机种子42保证可复现）

### 4.2 特征工程（17维）

| 类别 | 特征 | 说明 |
|------|------|------|
| **空间特征** | distance_km | Haversine起终点直线距离（核心特征） |
| 时间特征 | hour, weekday, is_weekend, month, day_of_month | 基础时间维度 |
| 用户特征 | user_type_Customer, user_type_Subscriber | one-hot编码 |
| 车辆特征 | bike_type_classic, bike_type_electric | one-hot编码 |
| 站点特征 | start_station_popularity, end_station_popularity | 站点流量（替代one-hot降维） |
| 时段标记 | is_morning_peak, is_evening_peak, is_night | 二值标记 |
| 周期编码 | hour_sin, hour_cos | 24小时周期性正弦/余弦编码 |

### 4.3 五模型横向对比 + 朴素基线

| 模型 | R² | MAE(分钟) | RMSE(分钟) | MAPE |
|------|-----|----------|-----------|------|
| 线性回归 | 0.1867 | 5.097 | 16.387 | 51.75% |
| 岭回归(Ridge) | 0.1867 | 5.097 | 16.387 | 51.76% |
| 决策树 | 0.1572 | 5.034 | 16.682 | 50.89% |
| **随机森林** | **0.2030** | **4.802** | **16.222** | **49.69%** |
| 梯度提升 | 0.2000 | 4.734 | 16.252 | 49.27% |
| 基线-均值预测 | -0.0000 | 8.309 | 18.171 | 113.12% |
| 基线-中位数预测 | -0.0438 | 7.695 | 18.565 | 77.01% |

**最佳模型：随机森林(Random Forest)**，R²=0.2030，MAE=4.802分钟。

**朴素基线对比结论**：均值/中位数基线R²≈0（无解释力）。随机森林相对均值基线MAE下降**42.2%**（8.309→4.802分钟），证明模型确实从特征中学习到了有效规律，而非简单"猜均值"。

### 4.4 特征重要性分析

随机森林模型的特征重要性排名（完整16项，month贡献为0已剔除）：

| 排名 | 特征 | 重要性 | 占比 |
|------|------|--------|------|
| 1 | **distance_km** | **0.6184** | **61.84%** |
| 2 | start_station_popularity | 0.0846 | 8.46% |
| 3 | end_station_popularity | 0.0819 | 8.19% |
| 4 | user_type_Subscriber | 0.0387 | 3.87% |
| 5 | day_of_month | 0.0347 | 3.47% |
| 6 | user_type_Customer | 0.0259 | 2.59% |
| 7 | hour | 0.0241 | 2.41% |
| 8 | hour_sin | 0.0184 | 1.84% |
| 9 | hour_cos | 0.0178 | 1.78% |
| 10 | weekday | 0.0175 | 1.75% |

**关键发现**：
- **distance_km单一特征贡献61.84%的解释力**，远超其他所有特征之和。这符合物理直觉——骑得越远，花的时间越长。
- 站点热度（起点+终点合计16.65%）是第二重要因素，热门站点可能存在排队、拥堵等增加时长的因素。
- 用户类型（会员vs临时）合计6.46%，临时用户骑行时长通常更长（不熟悉路线、休闲骑行）。
- 时间相关特征（hour/weekday/周期编码）合计约7.8%，说明骑行时长的时间规律性不强。

### 4.5 误差归因分析（分桶MAE）

按真实骑行时长分桶统计最佳模型（随机森林）的误差分布：

| 时长区间 | 样本数 | 真实均值(min) | MAE(min) | MAE占比 |
|---------|--------|--------------|----------|---------|
| <5分钟 | 8,295 | 3.39 | 3.045 | 2.7% |
| 5-10分钟 | 12,732 | 7.32 | 2.604 | 2.4% |
| 10-15分钟 | 7,574 | 12.28 | 3.361 | 3.0% |
| 15-30分钟 | 8,519 | 20.65 | 4.902 | 4.4% |
| 30-60分钟 | 2,489 | 38.96 | 13.625 | 12.3% |
| >60分钟 | 391 | 110.38 | 83.241 | **75.1%** |

**归因结论**：模型误差高度集中在**超长骑行（>60分钟）**——仅391条样本却贡献了75.1%的总MAE。这类骑行多为异地还车、观光绕行等特殊行程，其时长与直线距离相关性弱（实际路线远长于直线）。剔除该极端群体后，模型对常规骑行（<30分钟，占样本92%）的MAE仅2.6~4.9分钟，预测精度是实用的。

### 4.6 结果解读与业务含义

#### R²=0.20意味着什么？

R²=0.20表示模型能解释20%的骑行时长方差。这个数字"不高但合理"，原因如下：

1. **不可观测因素占主导**：骑行时长受大量模型无法捕捉的因素影响——个人骑行速度、红绿灯等待、路线选择（直线距离≠实际路线）、身体状态、坡道等。
2. **MAE=4.80分钟有实际价值**：对于平均13.3分钟的骑行，4.8分钟的平均误差意味着模型能提供±5分钟的时长估算，对行程规划、车辆周转预测有参考意义。
3. **距离特征是关键突破**：distance_km贡献61.84%的重要性，证明特征工程比模型选择更重要。

#### 业务应用

- **行程时间预估**：用户输入起终点，系统可基于距离+站点热度预估骑行时长，辅助出行规划。
- **异常检测**：实际时长远超预测值的行程可能存在车辆故障或异常停留，可触发运维检查。
- **车辆周转调度**：基于时长预测估算车辆从A站到B站的到达时间，优化调度路径。

## 五、小时级客流预测分析

### 5.1 问题定义

- **目标变量**：hourly_rides（每小时总骑行次数）
- **任务类型**：时间序列回归预测
- **数据粒度**：按日期+小时聚合，共748个小时样本
- **训练/测试划分**：时序划分（前80%训练=598小时，后20%测试=150小时），**不随机打乱**以保证时序合理性

### 5.2 特征工程（13维）

| 类别 | 特征 | 说明 |
|------|------|------|
| 基础时间 | hour, weekday, is_weekend, day_of_month | 日历特征 |
| 周期编码 | hour_sin/hour_cos, weekday_sin/weekday_cos | 捕捉24h和7天周期性 |
| **滞后特征** | **lag_1h, lag_24h** | 前1小时、前一天同小时的流量（核心特征） |
| 滑动平均 | rolling_3h_mean | 前3小时流量均值（平滑趋势） |
| 时段标记 | is_morning_peak, is_evening_peak | 高峰二值标记 |

### 5.3 五模型横向对比 + 朴素基线

| 模型 | R² | MAE(次/小时) | RMSE(次/小时) | MAPE |
|------|-----|-------------|--------------|------|
| 线性回归 | 0.8722 | 50.54 | 67.29 | 45.90% |
| 岭回归 | 0.8723 | 50.46 | 67.26 | 45.64% |
| 决策树 | 0.8797 | 43.31 | 65.28 | 23.30% |
| 随机森林 | 0.9441 | 30.67 | 44.49 | 18.97% |
| **梯度提升** | **0.9459** | **29.96** | **43.76** | **21.33%** |
| 基线-均值预测 | -0.0097 | 155.11 | 189.13 | 255.84% |
| 基线-中位数预测 | -0.0037 | 154.74 | 188.57 | 262.51% |

**最佳模型：梯度提升**，R²=0.9459，MAE=29.96次/小时。

**朴素基线对比结论**：基线R²≈0、MAE≈155次/小时。梯度提升相对均值基线MAE下降**80.7%**（155.11→29.96），相对决策树/线性模型亦有显著增益——集成模型（随机森林/梯度提升）比线性模型MAE低约40%，比单棵决策树低约30%。

### 5.4 特征重要性分析

| 排名 | 特征 | 重要性 | 占比 |
|------|------|--------|------|
| 1 | **lag_1h（前1小时流量）** | **0.7941** | **79.41%** |
| 2 | hour_cos（小时余弦） | 0.0450 | 4.50% |
| 3 | hour_sin（小时正弦） | 0.0324 | 3.24% |
| 4 | lag_24h（前一天同小时） | 0.0315 | 3.15% |
| 5 | rolling_3h_mean（3小时滑动平均） | 0.0298 | 2.98% |
| 6 | hour | 0.0280 | 2.80% |

**关键发现**：
- **滞后特征主导**：lag_1h单一特征贡献79.41%的重要性，说明小时级客流具有极强的短期自相关性——当前小时流量主要由前一小时流量决定。
- **周期编码有效**：hour_sin/hour_cos合计7.74%，捕捉早晚高峰的正弦波动，是仅次于滞后特征的重要因素。
- 线性模型R²也能达到0.87，说明客流规律本身很强；集成模型进一步提升到0.94。

### 5.5 误差归因分析（分桶MAE）

按真实小时流量分桶统计最佳模型（梯度提升）的误差分布：

| 流量区间 | 样本数 | 真实均值(次) | MAE(次) | MAE占比 |
|---------|--------|-------------|---------|---------|
| <20次 | 11 | 15.55 | 8.33 | 7.4% |
| 20-50次 | 14 | 32.57 | 17.84 | 15.9% |
| 50-100次 | 11 | 71.55 | 13.99 | 12.5% |
| 100-200次 | 18 | 160.61 | 37.12 | 33.2% |
| >200次 | 96 | 395.02 | 34.69 | 31.0% |

**归因结论**：客流误差集中在**高峰大流量时段**——100次/小时以上区间（114个样本）贡献了64.2%的总MAE。这与高峰时段流量绝对值大、波动剧烈有关（相对误差反而更低：>200次区间MAE占比31%但相对误差约8.8%）。对运营而言，高峰时段的±35次误差相对400次基数可接受，模型具备实用价值。

### 5.6 结果解读

#### R²=0.95的含义

客流预测R²=0.9459意味着模型能解释95%的小时级流量波动，预测效果优秀：

- 测试集覆盖约6天（150小时），预测曲线与真实曲线高度吻合
- 早晚高峰的峰值、午间低谷、夜间低谷都能准确捕捉
- MAE=29.96次/小时，对于峰值700-800次/小时的流量，相对误差约4-5%

#### 为什么客流预测比时长预测容易？

| 维度 | 时长预测 | 客流预测 |
|------|---------|---------|
| R² | 0.20 | 0.95 |
| 可预测性 | 低（个体行为随机性大） | 高（群体行为规律性强） |
| 核心驱动 | 距离(61.8%) + 大量不可观测因素 | 滞后客流(79.4%) + 周期 |
| 噪声来源 | 个人速度、路线、红绿灯 | 极端天气、突发事件 |

**本质区别**：时长预测是**个体级**预测，每个人的骑行行为差异巨大；客流预测是**聚合级**预测，个体差异在加总时相互抵消，宏观时间规律（早晚高峰、工作日/周末）非常稳定。

#### 业务应用

- **实时调度**：提前1小时预测各区域流量，动态调配车辆
- **人员排班**：基于客流预测安排运维人员高峰时段值守
- **异常预警**：实际流量显著低于预测值时，可能提示系统故障或天气异常

## 六、创新点总结

1. **Haversine距离特征**：从经纬度计算球面距离，distance_km成为时长预测第一重要特征（61.84%），证明特征工程的价值远超模型调参。

2. **四指标综合选K**：不依赖单一肘部法则，同时用SSE、轮廓系数、CH指数、DB指数交叉验证，K=4的判定可复现、有依据。

3. **10维站点特征**：不仅用流量和时长，还加入时间模式（早/晚高峰占比）、用户结构（会员占比）、空间位置、流量平衡度，聚类维度更丰富，业务可解释性更强。

4. **五模型横向对比 + 朴素基线**：每个预测任务都对比线性模型（线性回归/岭回归）、单树模型（决策树）、集成模型（随机森林/梯度提升），并加入均值/中位数朴素基线，量化证明模型相对"猜均值"的真实增益（时长MAE降42.2%、客流MAE降80.7%），结论有说服力。

5. **时序特征工程**：客流预测使用滞后特征(lag_1h/lag_24h)、滑动平均、正弦余弦周期编码，充分挖掘时间序列的自相关性和周期性，R²达到0.9459。

6. **误差归因分析**：对最佳模型按目标值分桶统计MAE，定位误差集中区间——时长预测误差集中在>60分钟超长骑行（贡献75.1%），客流预测误差集中在大流量高峰时段（贡献64.2%），为后续优化指明方向。

7. **聚类深化解读**：为每簇自动识别判别特征Top3并生成可解释的运营建议（通勤枢纽站/社区通勤站/低频休闲站等），聚类结果直接对接运营场景。

8. **代码工程化**：超参数统一收敛到代码顶部配置区、输入字段契约校验、固定随机种子，保证结果可复现、与成员2的标准表对接有据可查。

## 七、局限性与改进方向

### 7.1 当前局限

1. **数据时间跨度短**：仅1个月（2026年6-7月），无法分析季节性规律（冬季骑行量下降、雨雪天影响等）。
2. **时长预测R²有限**：0.20的R²说明个体骑行行为的随机性仍占主导，缺少实际路线距离、海拔坡度、天气等关键特征；误差归因显示>60分钟超长骑行贡献75%误差。
3. **聚类轮廓系数中等**：0.16的轮廓系数反映城市站点连续分布的本质，KMeans在空间连续数据上天然有局限。
4. **无外部数据**：缺少天气（温度/降水）、事件（演唱会/体育比赛）、地铁运营状态等外部变量，这些对客流有显著影响。

### 7.2 改进方向

| 方向 | 具体措施 | 预期收益 |
|------|---------|---------|
| 扩充特征 | 加入实际骑行路线距离(API路径规划)、海拔坡度、天气数据 | 时长R²有望提升到0.4+ |
| 扩充数据 | 获取全年12个月数据，分析季节性 | 客流预测可纳入月度/季节特征 |
| 模型升级 | 客流预测尝试LSTM、Prophet、XGBoost | 捕捉更长时序依赖 |
| 聚类升级 | 加入DBSCAN密度聚类、层次聚类对比 | 识别异常站点和空间密度模式 |
| 空间建模 | 加入站点间OD矩阵，构建图神经网络 | 挖掘站点间流量传导关系 |
| 误差优化 | 对>60分钟超长骑行单独建模或剔除后训练 | 时长预测MAE有望降至3.5分钟以下 |
